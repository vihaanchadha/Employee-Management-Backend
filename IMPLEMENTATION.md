# Employee API Implementation

## Overview

This implementation exposes the three requested employee-management endpoints as a secured Spring Boot REST API:

- `GET /api/v1/employee`
- `GET /api/v1/employee/{uuid}`
- `POST /api/v1/employee`

The solution prioritizes practicality, clean separation of responsibilities, and straightforward reviewer usability.

## Design

The application uses a controller-service structure:

```text
HTTP Request
    |
    v
EmployeeController
    |
    v
EmployeeService
    |
    v
In-Memory Employee Store
```

### Controller Layer

`EmployeeController` defines the HTTP routes and delegates employee operations to `EmployeeService`.

The controller is responsible for:

- Mapping HTTP requests to Java methods
- Extracting path variables and request bodies
- Returning appropriate HTTP status codes
- Returning `404 Not Found` when an employee UUID does not exist

### Service Layer

`EmployeeService` contains the employee-management logic and satisfies the challenge requirement to include a service layer.

The service is responsible for:

- Creating employee UUIDs
- Deriving an employee's full name
- Validating incoming employee data
- Storing and retrieving employees
- Returning all employees in a predictable order

### Employee Model

The provided `Employee` interface is implemented by `DefaultEmployee`.

Lombok is used to generate the required getters, setters, constructors, and builder while keeping the implementation concise.

### Create Request Model

`CreateEmployeeRequest` represents the expected JSON body for employee creation.

The request does not accept:

- `uuid`, because it is generated by the service
- `fullName`, because it is derived from `firstName` and `lastName`

This prevents clients from supplying values that should be controlled by the application.

## Persistence

The challenge states that an actual persistence layer is not required, so employees are stored in a thread-safe `ConcurrentHashMap`.

This approach:

- Avoids introducing an unnecessary database
- Supports concurrent API requests
- Keeps the implementation focused on the requested REST behavior

Employee data is cleared whenever the application restarts.

## Validation

Employee creation validates the following:

- First name is present
- Last name is present
- Salary is present and non-negative
- Age is present and non-negative
- Job title is present
- Email is present
- Contract hire date is present
- Contract termination date does not precede the hire date

Invalid requests return `400 Bad Request`.

## Security

All API endpoints require HTTP Basic authentication.

The API is configured as stateless because it is intended for service-to-service webhook requests rather than browser sessions.

CSRF protection is disabled because the API does not use cookie-based authentication.

Credentials are supplied through environment variables rather than being hard-coded in the source code:

```bash
export EMPLOYEE_API_USERNAME=employee-api
export EMPLOYEE_API_PASSWORD=local-challenge-password
```

HTTP Basic authentication should be used over HTTPS in a deployed environment.

## Running the Application

This project requires Java 17.

Set the authentication credentials:

```bash
export EMPLOYEE_API_USERNAME=employee-api
export EMPLOYEE_API_PASSWORD=local-challenge-password
```

Start the application:

```bash
./gradlew bootRun
```

The API will be available at:

```text
http://localhost:8080
```

## Example Requests

### Get All Employees

```bash
curl -i \
  -u employee-api:local-challenge-password \
  http://localhost:8080/api/v1/employee
```

### Get an Employee by UUID

```bash
curl -i \
  -u employee-api:local-challenge-password \
  http://localhost:8080/api/v1/employee/{uuid}
```

### Create an Employee

```bash
curl -i \
  -u employee-api:local-challenge-password \
  -X POST http://localhost:8080/api/v1/employee \
  -H "Content-Type: application/json" \
  -d '{
    "firstName": "Jane",
    "lastName": "Doe",
    "salary": 75000,
    "age": 28,
    "jobTitle": "Software Engineer",
    "email": "jane.doe@example.com",
    "contractHireDate": "2026-07-24T00:00:00Z",
    "contractTerminationDate": null
  }'
```

## HTTP Behavior

| Scenario | Status |
|---|---:|
| Valid employee list request | `200 OK` |
| Existing employee requested | `200 OK` |
| Employee does not exist | `404 Not Found` |
| Employee successfully created | `201 Created` |
| Invalid employee request | `400 Bad Request` |
| Missing or incorrect credentials | `401 Unauthorized` |
